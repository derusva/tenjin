# 简介

**状态：证据门控草案；当前不进入实现。**

本方案不再提议立即建设“手机互动导出按钮”。当前唯一允许继续评估的范围，是用户回到自己的家用 Windows 电脑后，对既有 X Bookmarks 做一次最多 20 条的手动、只读价值探针，验证这种延迟互动是否真的包含日语学习意图，以及完整往返是否优于已上线的“截图 → Coach → iPhone Tenjin 导入”。

当前基线已经现场核对：`main` 与本地 `origin/main` 均为 `529a784`；A1 完整备份恢复与 Coach Import 已在 `47996b0` 合入并推送，Coach 教学合同校准已在 `529a784` 合入并推送。`tenjin.coach-transfer/v1` 已从 `apps/web` 抽到 `packages/exchange`，在本地分支 `codex/coach-transfer-exchange` 提交为 `b6cf6e3`；该提交尚未推送或合入 `main`。仍未提交的是 `packages/reach-collector/`；2026-08-12 决策草案与本文在本轮作为独立文档变更收口，不与合同迁移提交混合。

现役截图路径可以覆盖小说、游戏和社媒，并且已经具备单设备 Coach 往返。Reach 只覆盖社媒账号中的延迟互动，不是共同采集路径，也不替代截图路径。Bookmark 只证明“用户想保存”，不证明“用户在这里遇到了学习卡点”；这正是本次探针首先要证伪或证实的假设。

功能概览：

- 不建设按钮、同步目录产品、后台任务或多来源编排；
- 只读取用户自然形成的最近 20 条 X Bookmarks，不要求为了实验改变收藏习惯；
- 先判断其中是否存在真实的日语理解或复习意图，再决定是否完成一次最多 3 条的 Coach 闭环；
- 完整计时到 iPhone Tenjin 确认入账，并与现役截图路径比较；
- 探针通过只授权后续编写 X 单源产品切片，不自动授权实现。

# 详细规则

## 评审裁决

| CC finding | 裁决 | 对方案的影响 |
|---|---|---|
| P0-1：多来源完整往返与约 6 分钟预算不匹配 | 接受 | 撤回多来源按钮；必须测从开始扫描到 iPhone 确认入账的完整时间，不能只测候选包落盘，也不能靠增加每批条目上限掩盖摩擦 |
| P0-2：跨批重复只能依赖 Windows 本地状态 | 接受 | 在持久幂等方案定案前，不允许可重复点击的产品入口；价值探针不触发 receipt 平台建设 |
| P0-3：只覆盖社媒且 Bookmark 不等于学习意图 | 部分接受 | “只覆盖社媒”是窄定位而非技术缺陷；“学习意图未经证明”是启动阻断项，因此先做 X Bookmarks 价值探针 |
| P1-1：连续 6 周、每周 3 条、近 30 天完成率 70% 是冻结启动门 | 原则接受，事实口径待来源 | 当前 `main`、工作树文档及本地 Git 历史中未找到这组精确阈值，不能把它写成已冻结项目规则；“没有真实供料与复习证据就不产品化”的原则成立。本方案改用下述可执行探针门，若 CC 有该阈值的权威来源，再另行归一 |
| P1-2：同步目录重演已作废 Capture Inbox 的失败模式 | 接受 | 探针不建设同步目录产品；任何临时跨设备手段都计入完整成本，不能被包装成已解决的传输层 |
| P1-3：YouTube 字幕缺时间、限流和维护 owner | 接受 | YouTube 整体退出本轮，不通过 X 单源价值门就不讨论字幕来源 |
| P1-4：多来源独立提交当前不成立 | 接受 | 多来源退出本轮；不把已知实现缺陷留到产品验收时边改边验 |
| P2-1：隐私逐条审查会回推时间成本 | 接受 | 探针默认仅保存在本机，只允许用户明确选中的非敏感公开内容进入外部 Coach；筛选时间计入总成本 |
| P2-2：prepare 后 raw state 变化会让 compile 失去映射 | 更正 | 当前 compiler 从保存的 `teaching-request.json` 读取 `excerptId → sourceExcerpt`，prepare 完成后不再依赖 raw state；真正的风险是 request 文件丢失、被篡改或与 generation result 不匹配，这些会由严格 parser 拒绝 |
| P2-3：Coach 合同搬家期间不应冻结依赖方案 | 接受 | `packages/exchange` 合同抽取落定、测试通过且 Git 边界清楚，是任何 Reach compile 探针的前置条件 |

## 关键决策

| 维度 | 决策 | 关键约束 | 原因 |
|---|---|---|---|
| 当前阶段 | 价值探针 | 不建设产品功能 | 先回答“值不值得重复使用”，不把 P0 转成工程清单 |
| 唯一来源 | X Bookmarks | 最多读取既有最近 20 条 | 去掉 YouTube 字幕等待和多来源维护面 |
| 手机行为 | 不变 | 不要求用户额外收藏实验材料 | 避免为了验证工具而制造虚假需求 |
| 探针入口 | 手动 CLI | 不做快捷方式、UI 或调度 | 按钮本身不能证明内容价值 |
| 产出上限 | 最多 3 条 | 沿用 Coach v1 | 与现役路径按同一批量比较 |
| 正式入账 | iPhone 主屏 Tenjin | 电脑不写第二本账 | 保持现有权威设备边界 |
| 重复防护 | 产品化前另立硬门 | 不接受只靠未备份的 Windows 文件 | 状态丢失后 Tenjin 当前无法拦截跨批重复 |
| 后续扩源 | 本轮禁止 | X 单源未通过前不讨论 Likes、History、YouTube 或 Instagram | 控制沉没成本与连接器维护面 |

## 当前产品与实现边界

- 已上线并推送：
  - Coach JSON 严格解析、逐条预览、原子导入、批次 import receipt、撤销重导；
  - IndexedDB v3、`focus` 内容身份、`.tenjin` schema v2 完整备份与恢复；
  - Coach import receipts 随完整备份保存和恢复。
- 当前本地分支已提交但尚未推送或合入 `main`：
  - Coach transfer 合同向 `packages/exchange` 的抽取，提交 `b6cf6e3`；
  - exchange 拥有完整 16 类错误码、64 KiB 边界和 canonical digest 测试，Web 仅保留带 `repairPrompt` 的兼容门面。
- 当前本地、未提交：
  - Reach collector、X / YouTube / note adapters、teaching prepare / compile。
- 当前 Tenjin 只按整批 canonical Coach transfer 的 digest 识别一次导入。
  - 同一 excerpt 被放进组成不同的两个批次时，两个 digest 不同，现有 receipt 不会提示重复；
  - `identityKey` 当前被带入派生 ItemView 并供搜索使用，不承担跨 capture 去重；
  - Reach `excerptId` 不进入 `tenjin.coach-transfer/v1`，Tenjin 无法用它拦截跨批重复。
- 当前 Reach 来源修订去重只能说明同一 Windows collector 是否再次看见同一 revision，不能证明 Tenjin 是否已经接受过该 excerpt。

因此，重复可用的按钮存在一条产品硬门：**影响跨批幂等的稳定身份必须在 collector 状态丢失和 Tenjin 完整备份恢复后仍然有效。** 仅在 Windows 本地增加一份 delivery receipt 不满足该门；直接接受重复学习条目也不满足该门。具体版本合同与迁移方案须在价值探针通过后另立设计，不在本次提前建设。

## 探针前置条件

- 只在用户自己的家用 Windows 电脑运行，公司电脑不参与。
- 用户另行明确授权 OpenCLI 读取 X Bookmarks、启动 daemon 和操作临时 Chrome 标签页；本方案本身不构成该授权。
- Chrome 已由用户自行确认登录预期 X 账号，Browser Bridge 已连接。
- Coach transfer 合同抽取已经提交并通过相关测试；探针记录实际 Git SHA，不从当前脏工作树冒充冻结基线。
- 使用自然形成的 Bookmark 样本，不提前要求用户“多收藏几条日文用于测试”。
- 探针数据默认只保存在家用电脑的隔离目录；完成复盘前不自动删除，之后删除仍需用户明确授权。

## 探针流程与计时

- 一次性安装和首次登录准备单独记录，不计入日常路径中位数；但某项准备如果每次都会复发，就必须计入日常总时间。
- `T_total` 从用户决定“现在运行 Reach”并开始操作时计时，到 iPhone 主屏 Tenjin 完成预览确认并显示导入成功时结束。
  - 浏览器重连、来源等待、候选筛选、Coach 等待、compile、跨设备传输、复制、粘贴和预览全部计入；
  - 不得把 Windows 端候选包落盘当作闭环终点。
- 使用 CLI 对 X Bookmarks 做一次最多 20 条的只读小批量读取。
  - 单次来源调用沿用当前 60 秒超时上限；超时或登录失败即记录失败，不为凑成功反复重试；
  - 不启用 X Likes、YouTube、Instagram、note 或任何多来源选项。
- 在送入外部 Coach 前，用户先判断哪些 Bookmark 是“我想回来理解或复习的日语”，哪些只是普通收藏。
  - 只选公开、非敏感且适合交给外部 Coach 的内容；
  - 该筛选时间计入 `T_total`。
- 若意图门通过，再生成最多 3 条教学建议、严格 compile 为 Coach transfer，并通过用户当次选择的临时方式送回 iPhone。
  - 临时方式可以是现有个人文件同步、同一 Coach 会话或其他用户已有渠道；
  - 本方案不预设该方式已低摩擦，所有动作与等待必须照实计时。
- 对现役截图路径记录可比基线：至少三次普通“截图 → Coach → iPhone Tenjin 确认”的完整时间及最终保留条目数，计算每个保留条目的时间中位数。
  - Reach 与截图基线必须使用完全相同的计时边界：都从用户开始该路径的第一个操作计时，到 iPhone 主屏 Tenjin 确认入账结束；
  - 两侧都包含全部 Coach／模型响应等待、复制粘贴、跨应用和跨设备动作，不得只从一侧扣除共享等待。

## 探针判定门

| Gate | 通过条件 | 不通过时 |
|---|---|---|
| G0 自然供料 | 最近最多 20 条既有 Bookmarks 中，至少 3 条由用户在看模型建议前判定为真实日语理解或复习意图 | 立即停止；Bookmark 不构成当前学习输入 |
| G1 完整成本 | 单次 Reach `T_total` 不超过约 6 分钟，且每个最终保留条目的时间不高于截图路径的实测中位数 | 停止产品化；不能用批量名义掩盖更高摩擦 |
| G2 候选质量 | 最多 3 条建议中，用户愿意保留至少 2 条；错误内容入账为 0 | 停止；来源或筛选精度不足 |
| G3 学习价值 | 至少一条保留项在后续真实复习或再次遇到时产生用户可感知的回忆或迁移价值 | 停止；“导入成功”不能替代学习价值 |
| G4 自发复用 | 完成上述体验后，用户在没有提醒、红点或待办的情况下主动要求再运行一次 | 归档方案；没有真实重复需求 |

G0–G4 全部通过，只说明 X Bookmarks 值得进入下一轮产品设计，不授权写按钮或扩大来源。任一 Gate 不通过，保留探针记录作为止损证据，继续使用已经上线的截图路径。

CC 提到的“连续至少 6 周、每周至少 3 条、近 30 天复习完成率至少 70%”可以作为更严格的后续候选门，但当前仓库没有查到它的已批准来源，Tenjin v1 也不保存 Reach 来源身份，无法直接计算来源级完成率。拿到权威来源并解决可测性之前，不把这组数字伪装成现行冻结规则。

## 探针通过后的下一步边界

- 下一步只允许起草 X Bookmarks 单源产品切片，先解决：
  - 跨批稳定身份如何进入 Tenjin 的持久、可备份边界；
  - collector 丢失、换机和 `.tenjin` 恢复后的重复保护；
  - 单次运行时间上界和来源适配失效时的止损；
  - 与截图路径的长期每条目成本对比。
- 在该设计通过独立评审和 owner 批准之前，仍不实现桌面按钮。
- X 单源产品真实使用成立后，才分别评估其他来源；YouTube 字幕必须另有超时、限流、部分失败和维护责任方案。

## 边界情况处理

| 场景 | 处理 | 结果 |
|---|---|---|
| Browser Bridge 未连接或账号未准备 | 停止探针，不自动登录 | 不产生采集成功证据 |
| 最近 20 条没有足够真实学习意图 | G0 失败 | 不生成 Coach 批次，不建设工具 |
| 读取超过 60 秒 | 记录超时并停止 | 不反复重试，不调整口径 |
| 候选含私密或敏感内容 | 留在本机，不送外部 Coach | 不为了样本量放宽隐私门 |
| 跨设备临时传输失败 | 计入 `T_total` 并记录闭环失败 | 不把 Windows 落盘算成功 |
| Coach 输出不合合同 | compiler 严格拒绝 | 不手改后伪装一次成功 |
| 用户重复运行同一探针 | 在持久幂等方案落定前禁止重复导入 | 防止用两个不同批次制造重复 Tenjin item |
| request 文件丢失、篡改或与 result 不匹配 | compiler 拒绝 | 不从 raw state 猜测或重建原文绑定 |

## 本轮明确不做

- 不实现桌面快捷方式、GUI、localhost companion 或 Tenjin 内按钮；
- 不创建同步目录产品、Inbox、红点、待办或后台调度；
- 不做 X Likes、YouTube History / Watch Later、Instagram 或 note；
- 不新增 delivery receipt、Coach transfer v2 或 `.tenjin` schema 迁移；
- 不因 collector 代码已经存在就把沉没成本当作继续建设的理由；
- 不把 Coach transfer 合同的本地提交误报为已经推送或合入 `main`；真实探针必须记录其执行基线 SHA。

# Explanation Policy

> 状态：可复用策略草案。它约束“解释如何选择与呈现”，不创建学习状态，不替代根 `HANDOFF.md` 的 R/L/P、事件和 proposal 规则。

## 1. 输入与优先顺序

解释器按以下顺序决定本次输出：

1. 用户当前明确问题、指定 focus、期望深度和输出格式。
2. 当前原句与必要 context；原句不写入通用画像。
3. 已确认的用户偏好，以及正式事件派生的相关 R/L/P 状态。
4. `GPT-inferred` 或 `hypothesis` 只能用于生成候选 focus，不能单独触发 skip、suppression 或状态更新。
5. 缺少证据时使用保守默认，并明确“不确定”或询问最小澄清问题。

用户显式提问始终可以绕过历史 `stable` / `suppressed` 的默认静默规则。绕过只影响本次解释，不自动改变状态。

## 2. 窄 focus

默认只解释 1–3 个真正阻塞理解或自然选择的点。

选择顺序：

1. 用户点名的词、结构或 A-vs-B；
2. 不理解就会改变整句关系的 attachment / 主干问题；
3. 作为整体才有意义的 collocation 或 chunk；
4. 会影响表达选择的语域、语气或事件结构；
5. 其余内容默认跳过。

如果用户说“只有 X 和 Y 不懂”，输出必须：

- 最多用一句话对齐整句语境；
- 只解释 X 与 Y；
- 不顺带复习其他基础成分；
- 除非 X/Y 的理解依赖某个未说明前提，否则不扩展第三个 focus。

如果没有明确卡点，不要自动逐词扫描整句。先给最可能的 1–3 个候选，并允许用户缩小范围。

## 3. Chunk 规则

解释和复习的最小单位应是“保留实际语言效果的最小完整单元”，不等同于单个词。

- 固定搭配、惯用表达、支配关系和有显著语域效果的结构以完整 chunk 呈现。
- 单词释义已知而组合义不透明时，解释组合后的功能，不重复列出每个词的基础义。
- chunk 必须保留必要的助词、补语或句法槽位；过度裁剪会造成错误泛化。
- 同一 lemma 的不同义项、语域或搭配可作为不同 usage facet；不要用一个总体“会/不会”覆盖全部用法。
- chunk 不是第四套 mastery 状态。若进入正式产品，它仍应映射到既有 item / usage facet，并分别由 R/L/P 证据决定状态。
- 例句 context 与画像分离；热画像只保存必要的偏好和瓶颈摘要。

## 4. A-vs-B：描述语言效果，不猜作者意图

默认问题应改写为：

> “在当前上下文中，A 产生什么语言效果；换成 B 后，意义、焦点、语气或文体会怎样变化？”

不要在没有直接证据时写“作者想要……”“作者故意……”或“作者选择 A 是为了……”。可观察、可比较的维度包括：

- 语义范围与信息焦点；
- 事件结构、完成度、持续性或因果关系；
- 说话人立场、评价强度与预设；
- 口语/书面、正式/随意、叙述/对话等 register；
- 固定搭配与自然度；
- 前后项的逻辑关系和预期落差；
- B 是不合语法、不自然、意义不同，还是在另一场景同样成立。

最小对比方法：

1. 尽量固定上下文，只替换 A/B。
2. 先说共同点，再说真正决定选择的差异。
3. 明确替换结果属于哪一类：`ungrammatical`、`unnatural`、`meaning-shift`、`register-shift`、`also-valid`。
4. 只提供能改变判断的一组最小例子。
5. 如果差异依赖更大上下文，明确写出依赖，不给伪确定结论。

只有存在作者访谈、注释、修订说明等直接来源时，才可以讨论实际创作意图，并附来源。

## 5. 场景与频率

频率和使用建议必须分开记录，避免把“常见”误写成“应该主动使用”。

推荐字段：

```yaml
scenario:
  - daily_spoken
  - narrative_written
  - business_formal
  - web_casual
  - exam_recognition
  - specialized_or_dated
frequency: high | medium | low | unknown
frequency_basis: corpus | dictionary_or_style_guide | bounded_source_set | model_estimate
production_target: active_use | recognize_only | context_dependent
confidence: high | medium | low
```

规则：

- 没有语料、辞书或明确来源时，不给精确频率；使用 `model_estimate` 和保守置信度。
- “JLPT 常见”不等于现实会话高频。
- 小说/旁白常见不等于日常会话自然。
- 商务书面常见不等于口头主动使用目标。
- 低频但当前材料关键的表达仍可解释；频率只影响学习投入建议，不决定当前是否正确。

## 6. Skip 规则

| 条件 | 默认动作 | 例外 |
|---|---|---|
| 用户明确限定 X/Y | 跳过所有非 X/Y 内容 | 仅补充理解 X/Y 必需的最小前提 |
| 用户明确说“这个知道/不要再讲” | 以后默认不主动展开 | 用户再次显式询问；出现新义项、新语域或新通道 |
| 正式状态为 `stable` / `suppressed` | 默认静默 | 显式问题始终绕过；真实失败按事件规则处理 |
| 只有 `GPT-inferred` 认为用户已掌握 | 不得据此 skip | 需要用户确认或正式证据 |
| 基础成分不影响当前卡点 | 跳过 | 它实际决定 attachment、歧义或 A/B 选择 |
| 完整句法分析不是当前问题 | 不展开整句 | 当前卡点就是长修饰、主干或省略恢复 |
| 相同 lemma 出现新 usage facet | 不继承旧 skip | 单独判断该 usage 的 R/L/P 与解释需要 |
| 证据不足或上下文缺失 | 不猜 | 标注不确定，或请求最小必要 context |

`skip` 是呈现策略，不是删除证据。它必须可被当前问题覆盖，也不能被解释模型直接写成 R/L/P 结论。

## 7. 默认输出合同

除非用户指定其他格式，按需使用以下最小结构：

1. **语境对齐**：最多一句话；用户已理解整句时省略。
2. **Focus**：1–3 个，先给 chunk 或结构功能。
3. **语言效果**：说明当前形式使什么更突出。
4. **最小对比**：仅在存在真实混淆时给 A-vs-B。
5. **场景建议**：场景、频率依据、主动使用或只需识别。

以下内容默认不输出：

- 与问题无关的逐词翻译；
- 教材式重讲全部基础语法；
- 无证据的作者心理或创作意图；
- 把模型估计包装成客观频率；
- 把一次正确回答写成永久掌握；
- 把本地个人画像细节回显到通用解释模板。

## 8. 反馈闭环

- 结构化的明确反馈可以形成用户事件。
- 自由文本若需要模型判断其含义，必须先成为 proposal。
- 用户接受后才可更新画像偏好；拒绝不得影响后续解释。
- 对某解释的“有用/无用”反馈只证明呈现适配度，不自动证明语言结论正确，也不直接修改 R/L/P。

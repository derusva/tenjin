# Learning Product Hypotheses

> 状态：候选能力清单，不代表已实现、已拍板或已进入路线图。
>
> 本文以根 `HANDOFF.md` 为上位合同。任何候选能力都必须保留事件账本、R/L/P 独立状态、确定性派生、隐私分层和 proposal 接受门。

## 1. 共同边界

所有优先级共用以下约束：

- Dynamic Profile 是派生视图，不是第二本账。
- 任何统一“熟悉度”只能用于内容组织或展示，不能替换 R/L/P。
- chunk 若进入正式数据模型，必须落到 item / usage facet；不能创建第四套 mastery。
- LLM 只能生成 proposal。未接受建议不能改变画像、R/L/P、调度或 skip。
- 用户明确提问始终可绕过默认静默；这不等于状态变化。
- 个人画像默认只在本机编译与保存；远端调用只发送当前任务所需的最小片段，并由用户显式触发。
- 新能力必须证明减少解释噪声或提高选择稳定性，不能只证明“模型能生成更多内容”。

## 2. 优先级定义

- **P0 — 边界与反馈地基**：先证明来源、状态和可撤销更新安全，再增加语义生成。
- **P1 — 高价值学习能力**：依赖 P0 的可信画像和 proposal 流，解决 chunk 与表达选择。
- **P2 — 纵向个性化实验**：需要足够长期数据、额外隐私同意或更高错误成本；不过 Gate 不进入产品默认路径。

## 3. P0：边界与反馈地基

### P0.1 Dynamic Learner Profile v0

**假设**

从正式事件、用户确认偏好和近期高价值瓶颈编译一个小型热画像，可以减少重复解释，同时不制造新的事实源。

**依赖**

- 现有事件查询与 R/L/P 派生视图；
- 带 `status`、`observed_at`、`source` 的画像 schema；
- 用户确认、supersede 和撤销路径；
- 本地持久化与最小片段检索；
- 明确的裁剪预算和隐私过滤。

**验收 Gate**

- 相同事件集合与相同已确认偏好，任意重建顺序得到相同热画像。
- 热画像中的 R/L/P 只读自正式派生状态；删除热画像后可完整重建。
- `GPT-inferred` / `hypothesis` 不会触发 skip、suppression、状态晋升或调度排除。
- 当前明确问题可以绕过画像中的默认静默。
- 默认热摘要控制在 2–4KB；不包含原句、人物、URL 或非必要 context。
- 本地画像缺失或损坏时，记录、查询与复习核心闭环仍可运行。

**主要失败模式**

- 画像变成影子状态机，与正式 R/L/P 漂移。
- 为压缩 token 而丢失来源和不确定性。
- “已掌握”推断导致错误静默，用户难以发现。

### P0.2 Explanation Priority Engine v0

**假设**

确定性地选择 1–3 个 focus，并显示选择理由，比“整句全解释”更能降低噪声。

**依赖**

- `explanation-policy.md` 的 focus、chunk 与 skip 合同；
- 用户当前问题的结构化 scope；
- 已确认偏好和相关 R/L/P 只读输入；
- “为什么选中/为什么跳过”的可解释 reason code。

**验收 Gate**

- 用户限定 X/Y 的测试中，不输出非 X/Y 内容，除非是理解 X/Y 必需的最小前提。
- 只有模型推断“已掌握”时，系统不得自动 skip。
- 新义项、新 usage facet 或新通道不会继承旧 skip。
- 每个 focus 都能返回稳定的 reason code；相同输入得到相同 focus 排序。
- 无 LLM 时仍能完成 focus 选择；LLM 只负责候选解释内容。

**主要失败模式**

- 优先级引擎实际变成不可解释的综合分。
- 为追求短输出而省略真正决定 A/B 的上下文。
- 把呈现 skip 错写成能力 suppression。

### P0.3 Feedback-to-Profile Proposal Flow

**假设**

把“这个知道”“只讲这两个”“一直有点模糊”等反馈转成可审计更新，可以让后续解释逐步适配，而不让模型直接写记忆。

**依赖**

- 复用或扩展 `proposal_created` / `proposal_accepted` / `proposal_rejected`；
- 结构化用户动作与自由文本模型抽取的明确边界；
- supersede、撤销和冲突处理；
- 画像编译器。

**验收 Gate**

- 结构化、明确的用户选择可记录为 `actor: user`；自由文本的模型解释必须先生成 proposal。
- proposal 未接受前，画像、skip、调度和 R/L/P 均无变化。
- 接受、拒绝、撤销和 supersede 都可审计；重复导入不重复应用。
- 拒绝的 proposal 不影响之后的 focus 排序。
- 将反馈映射为“已掌握”时，只影响获批的画像偏好；R/L/P 仍需正式学习证据。

**主要失败模式**

- 模型把礼貌反馈误读为掌握结论。
- 同一句反馈同时改画像、状态和调度，无法撤销。
- 用户需要逐条审批过多 proposal，重新制造整理欠账。

## 4. P1：高价值学习能力

### P1.1 Chunk Ledger

**假设**

以完整搭配和 usage facet 组织查询与复习，比孤立词条更能支持自然选择。

**依赖**

- item / usage facet 的身份和 merge 规则；
- chunk 规范化、槽位保留和 context 分层；
- R/L/P 对 usage facet 的独立证据；
- 搜索、去重和人工合并入口。

**验收 Gate**

- chunk 不创建总体 mastery；每个目标通道仍由既有 R/L/P 推导。
- 规范化不会删除决定意义的助词、补语或 register 信息。
- 同一 lemma 的不同 usage 不被自动错误合并；重复项可人工合并和撤销。
- 从原句进入查询、从查询返回来源 context 的路径可解释，context 缺失时正常降级。
- 在真实复习样本中，chunk 题相对孤立词题减少迟疑或混淆；未改善则停止扩展。

**主要失败模式**

- chunk 粒度过大，退化为不可复用整句。
- chunk 粒度过小，重新变成孤立词。
- 为方便搜索建立第二套 mastery 和调度。

### P1.2 A-vs-B Contrast Generator

**假设**

围绕可观察语言效果生成最小对比，比单一中文释义更能训练近义选择。

**依赖**

- `explanation-policy.md` 的 effect-not-intent 合同；
- 可选 Suggestion Provider；
- 当前 context、已确认相关证据与最小输出 schema；
- proposal 接受/拒绝与来源记录。

**验收 Gate**

- 输出至少区分共同点、决定性差异和替换分类。
- 无直接来源时不声称作者真实意图。
- 对 `also-valid`、`meaning-shift`、`register-shift`、`unnatural`、`ungrammatical` 有可测试的明确分类。
- 缺少 context 时返回不确定性或请求最小 context，不伪造唯一答案。
- 所有生成内容先进入 proposal；拒绝率和用户修订原因可见，但不被误称为客观语言学准确率。

**主要失败模式**

- 模型强行制造 A/B 差异。
- 把“该场景更自然”误写成另一形式永远错误。
- 用作者意图叙事掩盖缺少语言证据。

### P1.3 Context Carryover Summary

**假设**

导出一个极短、来源可追溯的当前学习摘要，可以减少新会话重复磨合，又不需要把完整画像交给外部模型。

**依赖**

- Dynamic Profile v0；
- 隐私过滤和显式导出；
- 固定字段与字符预算；
- 相关性检索，而非全量 profile dump。

**验收 Gate**

- 默认只包含已确认偏好、top 瓶颈摘要、相关 R/L/P 缺口和明确的 do-not-explain 指令。
- 不包含具体成绩、原句、人物、URL、完整历史或未接受推断。
- 目标长度为 300–600 个中文字符；超预算时按合同优先级确定性裁剪。
- 用户能在导出前预览、删除字段并明确确认。
- 新会话使用摘要后，重复基础解释减少，且未增加错误 skip。

**主要失败模式**

- 摘要成为未经审查的跨模型长期记忆。
- 为“个性化”携带过多敏感 context。
- 摘要过期却继续被当成当前事实。

## 5. P2：纵向个性化实验

### P2.1 Condition-aware Listening Observations

**假设**

用户自愿记录的训练条件可能帮助区分正常能力与特定状态下的波动。

**依赖**

- 明确同意和可删除的条件字段；
- 可比任务、足够样本与缺失值处理；
- 不把条件元数据写入能力事实；
- 隐私与 redaction 设计评审。

**验收 Gate**

- 样本不足时只显示 `unavailable`，不显示零效应或因果结论。
- 只报告相关性和不确定性；不做健康诊断。
- 不记录条件也不影响核心复习。
- 用户可以单独删除条件数据，而不破坏学习事件。
- 只有稳定、可复现且能改变训练选择的信号才保留。

### P2.2 Grammar-family Model Workbench

**假设**

把相关形式组织为共享核心、分支条件和最小对比，可能比孤立语法卡更利于迁移。

**依赖**

- 可版本化内容 schema；
- usage facet 与 chunk 基础；
- 人工审核和 proposal 流；
- 新例句与间隔复测任务。

**验收 Gate**

- 内容模型不改变 R/L/P 状态语义。
- 用户能在未见例句中说明分支条件，而不仅是复述中文定义。
- 间隔复测相对孤立卡有稳定改善；无改善则不扩展更多语法族。
- 模型生成的规则和例句必须经接受后才进入可复用内容。

### P2.3 Longitudinal Pattern Suggestions

**假设**

当长期证据足够时，系统可以提出“值得重建的模型”或“可能的跨项错误模式”。

**依赖**

- 足够长的正式事件历史；
- encounter 分母真实可用；
- 去重、通道分离和来源质量标记；
- 用户可审查的证据引用。

**验收 Gate**

- encounter emitter 未上线或分母不足时，模式结论必须为 `unavailable`。
- 每条模式建议列出支持与反例，不能只给综合分。
- 模式只能生成 proposal；不得批量改 item、R/L/P 或调度。
- 用户拒绝后不会反复以相同证据重提。

## 6. 非目标分层

### N0：硬边界，任何优先级都不做

- 用 Dynamic Profile 或单一 mastery 替换 R/L/P。
- 让 LLM、外部诊断稿或未接受推断直接写状态。
- 把本地个人画像提交到仓库、默认发往远端或复制进通用文档。
- 无证据声称作者真实意图、学习因果或客观语言学正确性。
- 为学习增强建立必需账号、必需云端或必需 LLM 运行时。

### N1：本轮 MVP 非目标

- 自动批量合并 chunk / usage facet；
- 全自动诊断疲劳、注意力或健康状态；
- 复杂仪表盘、综合能力分、排行榜、签到和 due 欠账；
- 后台持续抓取外部语料或未经用户触发上传 context；
- 用生成内容自动扩充大规模课程库。

### N2：有证据才重新评估

- 音频 capture 与真正的 L 通道音频训练；
- 自动 provider API、跨设备画像同步和更长上下文；
- encounter 驱动的密度指标与纵向模式挖掘；
- 更复杂的语法图谱、个性化实验或调度优化。

进入 N2 评估的前提不是“技术可做”，而是 P0/P1 的真实使用数据证明当前边界已稳定，并且新增能力解决了已观察到的问题。
